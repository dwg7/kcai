# 共創の規律：蒸留ではなく、足していく作業として

インスタンスを作る作業は、外から見ると「公開資料を AI で要約して、置き換えるもの」（蒸留）に見えることがある。そう受け取られると、出典の書き手への敬意が欠けた作業、専門家の知を吸い上げる作業、という否定的な印象につながりうる。この文書は、kcai が**共創**であるために、書き手が守る規律と、参加者の士気の拠りどころを整理する。**提案であり、採否は hfu が決める。**（原則 13 に従い、外への説明ではなく、書き手と管理者のための規律として書く。）

## 蒸留と共創の違い

| 観点 | 蒸留と見られる作業 | kcai がめざす共創 |
|---|---|---|
| 出典 | 元を縮約して、元の代わりに置く | 元へ案内する。転載せず、版と取得日を記す |
| 付け加えるもの | 縮約だけ | 比較、食い違い、版のずれ、範囲（語り得ぬこと）、ケースでの確認 |
| 人の役割 | 出来上がったものの後工程の確認 | 問いを立て、自分のケースで確かめ、線を引く |
| 誤り | 気づかれにくい | 検証と訂正が記録に残る（`DECISIONS.md`） |
| 元の書き手との関係 | 取り出す | 帰属を明記する。見つけた誤りや古さは、事実として適切な窓口へ伝えうる（任意） |
| 公開されていない知識 | 取り出そうとする | 書かない。語り得ぬこととして範囲を示す |
| 目的 | 学習用の素材やデータの作成 | 人が読み、人が確かめ、次の人がたどること |

## 規律

1. **戻す。** 踏み跡は、出典の代わりにならない。読んだ人が出典へ戻れるようにする（出典、版、取得日、該当箇所）。一次資料の本文は転載しない（原則 6）。
2. **足す。** 一つの踏み跡に、要約以外に何を足したかを意識する。足すものの例: 複数の出典の比較、食い違いや版のずれの指摘、確かめられた範囲と確かめられない範囲、設問や定義が同じかの確認、実務のケースへの当てはめ。要約だけの踏み跡は `draft` として置いてよいが、それを目標にしない。
3. **記す。** 誰が、どの手法で、どこまで確かめたかを記録する（`authors`、`reviewed_by`、`docs/responsible-use.md`）。AI が書いたことを隠さない。人が確かめていないことを、確かめたように見せない。
4. **確かめ、直す。** 独立した検証と、人の確認を重ねる。誤りが見つかったら直し、直した跡を残す。
5. **返す（任意）。** 出典の誤りや古さ、版の食い違いを見つけたとき、事実として、出典の窓口に伝えることができる。これは参加者の個人の判断で、kcai は求めない（原則 10、11）。
6. **越えない。** 公開されていないこと、組織の中の知識、本人が公開してよいと判断していない経験は、書かない（原則 7、11）。分からないことは、分からないと書く（`docs/unsaid.md`）。
7. **言葉を正確にする。** 作った方法を、事実で述べる。「たどる」「確かめる」「残す」「返す」を使い、実態以上の「共創」や「完成」を名乗らない。

## 共創を名乗る条件

「共創」は、人の関与が記録されて初めて成り立つ。インスタンスの README の「位置づけと作り方」に、現状を事実で書く（例: 確認者の人数、問いを出した人がいるか、確認済みの踏み跡の件数）。人の確認がまだなければ、そう書き、「共創の途上」として扱う。

最初のインスタンスの現状（2026-10-21）: 約 100 件の踏み跡のすべてが `draft`で、実務者による確認の記録は 0 件。一方、人（hfu）が問いを立て、出典の帰属や設問の同一性などの誤りを指摘して直した記録は、`DECISIONS.md` に残っている。実務者による確認を重ねることが、共創としての次の段階である。

## 士気の拠りどころ

参加する人にとって、この作業に意味があるのは、次のときである。

- 自分の問いが、踏み跡として残る。
- 見つけた食い違いや誤りが、直された記録として残り、次の人の手間を減らす。
- 自分の AI の費用で、自分の仕事のために使ったものが、そのまま共有地への貢献になる（AI は共有しない）。
- 参加が個人の判断で、組織に何も求められない（原則 10、11）。個人の研鑽の跡として残る（下の「研鑽としての関わり」）。
- 帰属の表示は、本人の選択に任される。

## 研鑽としての関わり

公務や、組織の規則のもとで働く人にとって、「研鑽」という概念が手がかりになる。研鑽は、学問や技能を磨いて深く究めることで、「研鑽を積む」のように継続的な努力を表し、**自発的な取り組み**に使われる（指示された研修とは区別される）。kcai の関わりは、この意味で、個人の研鑽として説明できる。

- **鍛える＝研鑽を積む。** 「それぞれが自分の AI で鍛えていく」は、各人が出典をたどって学び、確かめることである。踏み跡は、その学びの跡が、公開できる範囲で残ったものと見られる。
- **自発であること。** 研鑽は自発のものなので、原則 10（組織に働きかけない）と整合する。kcai は、参加を職務や義務として求めない。
- **公開できる範囲に限ること。** 公務員などには、職務上知りえた秘密を漏らさない義務（国家公務員法第 100 条、地方公務員法第 34 条など）がある。原則 7、11（公開された資料と、個人として公開してよい経験に限る）は、この義務と同じ向きの約束である。
- **kcai は、各人の規則について助言しない。** 兼業、講演・執筆、職務専念、秘密の扱いなどの規則は、所属ごとに異なる。参加するかどうか、どこまで公開してよいかは、各自が所属の規則に従って判断する（今回の調査では、国家公務員の無報酬の講演・執筆に許可が要るかを確かめられなかった）。
- **「研鑽」を、前に出さない。** 研鑽の言葉で参加を勧めたり、特定の組織の公式な取り組みや推薦と読める表現にしたりしない（原則 13）。個人の研鑽として説明できる、という整理にとどめる。

## 提案（未決。採否は hfu）

- `PRINCIPLES.md` に、原則として加えるか: 「踏み跡は、出典の代わりではなく、出典への案内と、人が足した問いと確認の跡である。」
- `docs/triage.md` の審査の観点に、「足したものがあるか」「確かめていないことを確かめたように見せていないか」を加える。
- ひな形の README の「位置づけと作り方」に、人の関与の現状を書く欄を加える。
- 出典の誤りを窓口へ伝える場合の、伝え方の心得（事実のみ、根拠を添える、返信を求めない）を、`docs/` に短く書く。
