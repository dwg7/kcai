## kcai としてのレビュー（懸念と、まだ確かめていないこと）

1. **人の確認がまだ 0 件**。全塊が `draft`。形式は整ったが、「人が確認すると `reviewed` になる」循環はまだ一度も回っていない。熟練職員のコメントが最初の試験になる。
2. **一次資料への依存が強い**。要約と出典のみとする方針は守れているが、読者にとっての価値は「どの条文を、どの順で読むか」にあり、それが出典の言い換えに近づくと価値が薄い。`finding` / `review-` の塊の比率が、価値の目安になる。
3. **検証の自動化の限界**。検査は構文と参照の整合まで。数値や条番号の正しさは検証者（AI または人）に頼る。`cites` の該当箇所から原文を自動取得して照合する仕組みは、著作権と取得の安定性の両面で、まだ設計していない。
4. **インスタンス間の再利用は未検証**。他分野（河川占用など）で、必須の核と拡張がそのまま通じるかは、2 つ目のインスタンスを作るまで分からない。
5. **PDF と README 索引が二重管理**。索引が実質的に並び順を決めている。索引の抜けは警告で拾えるが、並び順の意図は文書化していない。
