# インスタンスの適合基準

kcai に準拠するインスタンス（分野別リポジトリ）が、安定して運用されるために満たす制約です。
「必須」は満たさないと kcai 準拠を名乗れない項目、「推奨」は望ましい項目です。

## 1. 構成（必須）

- `README.md`、`AGENTS.md`、`CLAUDE.md`（`@AGENTS.md` のみ）、`DECISIONS.md`、`LICENSE`、`knowledge/` がある。
- `README.md` に、管理責任者と準拠する kcai の版（コミットまたは日付）を明記する。
- ライセンスは CC0 1.0。

## 2. 踏み跡（必須）

- すべて `docs/knowledge-format.md` の**必須の核**に適合し、`scripts/validate_knowledge.py` が通る。必須の核の外側（タグ、関係の種類、出典の引用、見出し）は、インスタンスと書き手が自由に拡張してよい（原則 9）。
- 検査は CI（PR 時）で自動実行し、失敗した PR はマージしない。
- 踏み跡は `knowledge/` 直下に置く。1 ファイル 1 主題、`id` とファイル名は一致させる。
- `id` は変更しない。名前を変えたいときは新しい踏み跡を作り、旧踏み跡を `deprecated` にして `related` で結ぶ。削除はしない。

## 3. 信頼度の遷移（必須）

- `draft` → `reviewed`: 人が出典と照合して `reviewed_by` に記録した場合に限る。AI が自分で `reviewed` にしてはならない。
- `reviewed` → `stable`: 管理責任者が承認し、`DECISIONS.md` に記録する。
- 内容を実質的に変えたら `status` を `draft` に戻し、`reviewed_by` を空にする（軽微な誤字修正を除く）。
- `updated` は実質変更のたびに更新する。

## 4. 出典と著作権（必須）

- 一次資料（法令、規程、公式手引き等）は要約と出典提示にとどめる。本文や図版を転載しない。
- 出典は URL を含め、取得できる形で書く。URL が失効したら踏み跡を `draft` に戻して再確認する。
- 公開不可情報、個人情報、契約上の秘密を含めない。

## 5. AI の扱い（必須）

- インスタンスに特定の AI 製品・モデル・API・契約を持ち込まない（AI 向け案内は `AGENTS.md` に集約し、製品名依存の手順を必須化しない）。
- AI 支援の有無は踏み跡ごとに `authors` へ記録する。
- AI は審査結果と推薦までを担当し、承認・マージはしない。

## 6. 運用（必須）

- 判断が分かれた事項は、選択肢と理由を `DECISIONS.md` に追記する。既存の記録は削除しない。
- 管理責任者が不在・不明になったインスタンスは、新規提案の受付を止め、`README.md` にその旨を明記する。

## 7. 関わり方（必須）

- 原則 10〜13（`PRINCIPLES.md`）に従う。組織に採用や参加を求めない。提案は公開された資料と個人として公開してよい経験に限る。宣伝や勧誘をせず、組織の公式な取り組みや誰かの推薦を受けたものとして示さない。
- `README.md` に、この関わり方を明記する（ひな形の「関わり方」を使う）。

## 8. 推奨

- 出典の台帳（`SOURCES.md`）を置き、踏み跡の `cites` で、出典の版と該当箇所を示す。更新の速い出典には、確認日を保つ。
- タグ・関係の使われ方を、`scripts/build_index.py` で集計し、新しいタグを作る前に既存のものを再利用する。
- 問いから得た発見を、`finding` などのタグや `review-` の踏み跡で残す（`docs/asking.md`）。

- README.md に知識の索引（踏み跡へのリンク一覧）を置く。リンクの順序を、まとめの文書（PDF）の並び順の基準にする。
- 閉じた環境でも読める版付きの配布物（単一 Markdown と zip、目次付き）を作れるようにする（`docs/distribution.md`）。
- 踏み跡を 1 つの PDF にまとめられるようにする（`scripts/build_pdf.py`）。分野の関係者に内容を確認してもらうとき、リポジトリそのものではなく PDF を見せられる。

- 踏み跡が増えたら、分野別の索引（`knowledge/README.md`）を置く。検査対象外とする。
- 定期的な出典の再確認を、管理責任者の判断で行う（巡回の頻度は各インスタンスが決める）。
- kcai 側の改定は `DECISIONS.md` に記録されるため、準拠版を上げるときは差分を確認する。
