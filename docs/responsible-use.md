# 責任ある使い方：内容の無謬ではなく、手法と位置づけの明示

kcai は、AI が下書きした知識を共有する。「AI の責任ある使い方」を問われたとき、kcai は**内容が完璧であること**を約束しない。約束するのは、次の 4 つである。

1. **手法を明示する**: 誰が（AI か人か）、どの出典から、どう確かめて書いたか。
2. **位置づけを明示する**: これは実験区画（サンドボックス）の成果であり、確認前は仕事の根拠にしない。
3. **責任の所在を明示する**: 内容に責任を持つのは人であり、AI ではない。
4. **訂正の経路を持つ**: 誤りが見つかったとき、直し、履歴を残す。

## 国際的な議論との対応

次は、各文書の**二次的な解説**を読んだ範囲での整理である（原文は未読。引用や適用の前に、原典で確かめること）。

| 議論 | 要点（解説による） | kcai での対応 |
|---|---|---|
| OECD AI 原則（2024年改訂） | 透明性と責任ある開示（文脈に応じた意味のある情報）、説明責任、人の主体性と監督を保つ能力 | `authors`、出典、`reviewed_by`、人の審査 |
| NIST AI RMF 1.0 | 任意の枠組み。「有効で信頼できる」を含む複数の特性があるが、チェックリストではなく、用途ごとの文脈（Map）とリスクに応じた管理を求める。説明責任と透明性を対にする | 用途を限定し（下記）、リスクに応じて確認の深さを変える |
| AI 事業者ガイドライン 第1.1版（総務省・経済産業省、2025年3月） | 人間中心、透明性、アカウンタビリティなど。リスクベースアプローチ。開発者・提供者・利用者の役割に応じた取組 | 提案者は利用者、インスタンスの管理者は提供者に近い。役割を README に書く |
| 学術出版（ICMJE、COPE） | AI は著者になれない。責任は人が負う。AI の使用は手法として開示する。開示は責任を移すのではなく、責任の所在が分かるようにする | `authors` に「AI 支援あり/なし」、人の確認者の記録 |
| EU AI 規則 第57条（規制のサンドボックス） | 管理された環境で、限られた期間、当局と合意した計画のもとで試す。安全策があり、重大な危険を軽減できなければ停止できる。提供者の責任は残る | 比喩として参考にする。kcai は法的な意味のサンドボックスではない |

共通する骨格は、**完璧な出力ではなく、透明性・説明責任・人の監督・リスクに応じた管理**である。

## kcai の「サンドボックス」の意味

kcai では、`status: draft` の踏み跡を、**実験区画の成果**として扱う。

- 公開情報だけで書く（原則 7）。実在の個人情報や、非公開の情報を入れない。
- 出典の要約にとどめ、一次資料の本文を転載しない。
- `draft` は「人が確認していない」ことを意味する。**`draft` の踏み跡を、そのまま業務の根拠、契約、安全に関わる判断に使わない。** 使うときは、出典で確かめる。
- `reviewed` は「確認者が、記載したケースで確かめた」ことを意味する。完全性や最新性の保証ではない（`as_of`、`freshness`、`unsaid` で範囲を示す）。

「サンドボックス」は、EU AI 規則の規制のサンドボックスとは別の意味で使う（規制当局との合意や、法的な保護を意味しない）。誤解を避けたいときは、「実験区画」と書く。

## なぜ予防が要るか（最初のインスタンスの経験）

- AI が書いた文章は、整っていて、もっともらしい。人が確認していなくても、確認済みに見える。
- 最初のインスタンスの全 101 件の踏み跡は `draft` で、人の確認は 0 件。それでも PDF にまとめると、確認済みの資料に見える。
- 独立した検証者による一次資料との照合で、数字、条番号、版、設問の同一性の誤りが、何度も見つかった。AI の下書きは、手法として検証を前提にしても、誤りを含む。
- したがって、「責任ある使い方」の根拠は、無謬ではなく、**誤りがありうることを前提にした手法の公開と、確認の記録**になる。

## 無責任な使い方と誤認されないための表示（提案。採否は hfu）

| 場所 | 表示の内容 |
|---|---|
| kcai の README | 位置づけ（実験区画、`draft` の意味、使う人の責任）の短い節 |
| インスタンスの README、PDF の表紙 | 「この資料の作り方」（AI の下書き、独立した AI による照合、人の確認の有無）と、「使う前に出典で確かめる」 |
| 踏み跡（任意） | 手法の記録: 例 `method: [ai-draft, independent-ai-check, source-reread]`。形式の核は変えず、自由な拡張とする |
| 審査（`docs/triage.md`） | 公開不可情報、出典なしの断定、一次資料の転載、特定製品への依存に加え、「確認済みに見える書き方」を直す |
| 訂正 | 誤りが見つかったときは、踏み跡を直し、`DECISIONS.md` に記録する（履歴は消さない） |

## 守らないこと

- 「AI が書いたから間違いがあっても仕方がない」という免責。責任は人（提案者と管理者）にある。
- 「人が確認したから正しい」という保証。確認の範囲（ケース、時点）を書く。
- 安全や契約に関わる判断への、`draft` の使用。
